# MPC A06R4 — AltDSS parameter extraction separated from LinDistFlow control

- **Native parameter acquisition:** `capture_ieee123_parameters_altdss.py` starts independent AltDSS contexts and loads the existing unmodified IEEE-123 DSS master files. It reads bus-phase voltage bases, current phasor magnitudes, switch positions, regulator winding taps, capacitor state, and current PV active power. It cannot access or mutate the OpenDSSSim Plant.
- **Controller-side pure compiler:** `opendsssim.controllers.mpc.ieee123_lindist` consumes pinned A05/A06 static data and separate native readback; it never imports AltDSS or calls a native solution.
- **Approximation is intentional:** lossless multiphase LinDistFlow with balanced-angle off-diagonal terms; native line R/X/length; delta load 50/50 phase power allocations; idealized transformer in per-unit; affine regulator tap-to-voltage lift; static persistence forecasts; P2 uniform experimental priorities and voltage-only thermal scope. These are **not** nonlinear AC-equivalent models.
- **Limitations:** All predicted voltage/flow quantities require independent native AC comparison. P1 shared three-phase capacitor-bank action-channel mapping remains a separate adapter requirement. P2 bus-level radiality and branch statuses require native closed-loop action-boundary qualification. P2 load priorities/curtailment, thermals remain unqualified. The resulting JSON is an experiment prototype, not a completed MPC controller or PESGM performance result.
- **Physical model:** never modify B00, A03/A04/A05/S06 runtime, simulator, Plant, feeders or controller core. Native AltDSS readback here is **offline model-data acquisition only**. For actual control, A07 must use official `controller_context()` and `env.step()` action boundary.
